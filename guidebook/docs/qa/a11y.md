# Доступность гайдбука Hamkor Bank: аудит по WCAG 2.2 AA

**Дата:** 27.10.2026
**Что проверяли:** замороженная сборка на `http://localhost:4600`. Страницы: `/`, `/expat/`, `/local/`, `/faq/`, `/topic/work/`, `/topic/arrival/`, `/guide/arrival-72h/`, `/guide/bank-card/`, `/guide/car-import/`, `/guide/emergency/` и страница 404 (`/404.html`; см. замечание 22). Язык: только русская версия.
**Стандарт:** WCAG 2.2, уровень AA.
**Чем проверяли:** axe-core 4.x (наборы правил wcag2a/aa, wcag21a/aa, wcag22aa и best-practice) на ширине 390×844 и 1440×900. Остальное проверено сценариями Playwright/Chromium:
- обход всех страниц клавишей Tab на обеих ширинах. Видимость фокуса оценивали по разнице пикселей, а перекрытие фокуса панелями — по геометрии;
- проверка меню и поиска: куда попадает фокус, держится ли он внутри, работает ли Escape;
- контраст по пикселям: фон снимали со скриншота, на котором текст сделан прозрачным;
- эмуляция `prefers-reduced-motion`, увеличение текста до 200%, ширина 320 px, межстрочные интервалы по 1.4.12, режим `forced-colors`;
- поведение «шторки» при переходе на другую страницу, в том числе при сбое JS.

**Итог: сайт не соответствует WCAG 2.2 AA.** Найдено 22 замечания: 1 блокер, 5 серьёзных, 7 умеренных, 9 мелких.

> Исходники меняются, пока идёт аудит (в `main` появились новые коммиты). Поэтому исправления привязаны к **селекторам и функциям**, а не к номерам строк.

## Коротко для владельца

Сайт в целом построен аккуратно. Заголовки идут в правильном порядке, кнопки-иконки подписаны, частые вопросы сделаны стандартными раскрывающимися блоками. Режим «уменьшить движение» работает хорошо, на узком экране 320 px ничего не ломается. Почти весь мелкий серый текст проходит по контрасту.

Есть шесть проблем, из-за которых часть людей не сможет пользоваться сайтом или будет делать это с трудом:

1. **Тёмная «шторка» при переходе может закрыть страницу навсегда.** Это случается, если скрипт не загрузился (плохая мобильная сеть) или упал с ошибкой. Человек видит только зелёный экран с логотипом и не видит текста. Чинится несколькими строками CSS.
2. **Меню и поиск неудобны тем, кто управляет сайтом с клавиатуры или через экранного диктора.** При открытии меню курсор остаётся снаружи. Клавиша Tab уводит его на страницу, скрытую под затемнением.
3. **На главной не видно, где сейчас курсор клавиатуры.** Рамка тёмно-зелёная на тёмно-зелёной шапке.
4. **На телефоне выделенная ссылка уезжает под нижнюю панель** («Назад / Главная / Поиск / Меню»), и человек не видит, где находится.
5. **Главная кнопка «Я локальный кандидат» — белый текст на светло-зелёном фоне.** Его плохо видно на солнце и людям со слабым зрением (контраст 3,1 при норме 4,5).
6. **При крупном шрифте в настройках телефона** (так делают многие люди старшего возраста) шапка и нижняя панель «разъезжаются», появляется горизонтальная прокрутка, а ссылка «Перейти к содержанию» постоянно висит поверх шапки.

Первые четыре пункта — работа на 1–2 дня для одного разработчика. Пятый — замена одного цвета. Шестой — около дня вёрстки.

## Блокер

### 1. «Шторка» перехода остаётся навсегда, если на новой странице не сработал JS

- **Страницы:** все (любой переход по ссылке внутри сайта без `prefers-reduced-motion`).
- **WCAG:** Требование соответствия 5 (Non-interference). Технология (анимация), которая не нужна для смысла, не должна закрывать содержимое. Нарушает также 2.4.7 и 1.4.3: всё содержимое невидимо.
- **Что происходит:**
  - Старая страница по клику ставит `sessionStorage['gb-cover']` (`coverAndGo` в `src/lib/client.ts`).
  - Встроенный скрипт в `<head>` новой страницы (`takeCover` в `src/layouts/Base.astro`) сразу добавляет `html.is-covered`. Это непрозрачная `.curtain` на весь экран, `z-index: 90`.
  - Снять её может только `liftCover()`. Она вызывается **последней** в `initSite()`, после девяти других функций.
  - Если модуль `/_astro/*.js` не загрузился или любая из предыдущих функций бросила исключение, шторка не уходит никогда.
- **Доказательство:**
  - Сбой загрузки JS эмулировали блокировкой `/_astro/*.js`. Через 3 с: `/guide/work-time/`, `html.className = "js is-covered"`, у `.curtain` `visibility: visible`, `transform: none`. Скриншот — сплошной тёмно-зелёный экран с логотипом.
  - Отдельно эмулировали исключение (`window.IntersectionObserver = undefined`, падает `reveal()`). Через 2,5 с: `"js is-covered"`, шторка висит.
  - Экранный диктор при этом читает страницу (у шторки `aria-hidden`). А зрячий пользователь, в том числе с диктором, видит пустой экран.
- **Исправление (все три пункта, проверено):**
  1. Страховка на CSS, работает даже без JS. В `src/styles/global.css`:
     ```css
     .is-covered .curtain {
       visibility: visible;
       transform: none;
       animation: curtain-failsafe 1ms 1.6s forwards; /* если JS не снял шторку — она уходит сама */
     }
     @keyframes curtain-failsafe { to { visibility: hidden; } }
     ```
     С этой правкой и заблокированным JS у `.curtain` `visibility: hidden` через 1,6 с (проверено).
  2. В `initSite()` (`src/lib/client.ts`) вызывать `liftCover()` **первой**, а остальные функции обернуть, чтобы одна ошибка не роняла всё:
     ```ts
     export function initSite() {
       liftCover();
       for (const step of [bindShell, () => applyAudience(currentAudience()), markCurrentNav, callouts, reveal,
                           () => (cleanupProgress = progress()), journeyRail, phoneDemos, followingGuide,
                           headerOnScroll, illustrationsOnScroll]) {
         try { step(); } catch (e) { console.error(e); }
       }
     }
     ```
  3. На старой странице: если переход не состоялся (сеть пропала, ответ 204, загрузка файла), снять `is-covering`:
     ```ts
     window.setTimeout(() => (location.href = link.href), CURTAIN_IN);
     window.setTimeout(() => document.documentElement.classList.remove('is-covering'), CURTAIN_IN + 4000);
     ```

## Серьёзные

### 2. Меню (drawer) и поиск: фокус не попадает внутрь и не удерживается, фон не блокируется

- **Страницы:** все. Открытие через `.dock [data-sheet]` на телефоне и `.topbar [data-sheet]` на компьютере.
- **WCAG:** 2.4.3 Focus Order (A), 2.4.11 Focus Not Obscured (AA), 1.3.2/4.1.2: `aria-modal="true"` обещает модальность, которой нет.
- **Доказательство:**

  | Сценарий | Результат |
  |---|---|
  | 390, Enter на «Меню» в доке | `#drawer` открыт, **фокус остаётся на `button "Меню"` снаружи**. Причина: в `openSheet()` селектор `'[data-close].icon-btn'`, а у кнопки класс `.tb-icon`, поэтому `focus()` не вызывается |
  | 1440, Enter на `.tb-menu` | Фокус снаружи. **Первый же Tab уходит в `main`** («( 04 ) РАБОТА И ДЕНЬГИ», ссылки статьи, `summary`): элементы под затемнением |
  | 390/1440, поиск | Фокус в `#search-input` (хорошо), но **первый Tab уходит на `.guide-fab-btn` за пределами диалога**, затем на `.skip` и `.tb-back` |
  | Shift+Tab с кнопки «Закрыть» | Уходит наружу (`button "Меню"` / `a "Экстренные номера"`) |
  | Escape, кнопка «Закрыть» | Закрывают, фокус возвращается на кнопку, которая открыла окно. **Работает** |
  | У фона нет `inert` и `aria-hidden` | `main.inert === false` |

- **Исправление.** Лучший вариант — перевести `.sheet` на нативный `<dialog>` и `showModal()`: перехват фокуса, `inert` для фона и Escape браузер даёт сам. Минимальная правка в `src/lib/client.ts`:
  ```ts
  function setInert(on: boolean) {
    document.querySelectorAll<HTMLElement>('body > :not(.sheet):not(script):not(template)')
      .forEach((el) => (el.inert = on));
  }
  function openSheet(id: string) {
    const sheet = document.getElementById(id);
    if (!sheet) return;
    closeSheets();
    lastFocus = document.activeElement as HTMLElement;
    sheet.setAttribute('data-open', '');
    setInert(true);
    document.body.style.overflow = 'hidden';
    if (id === 'search') {
      loadIndex();
      setTimeout(() => document.getElementById('search-input')?.focus(), 60);
    } else {
      sheet.querySelector<HTMLElement>('[aria-current="page"]')?.scrollIntoView({ block: 'center' });
      sheet.querySelector<HTMLElement>('[data-close].tb-icon')?.focus({ preventScroll: true }); // было .icon-btn
    }
  }
  function closeSheets() {
    const wasOpen = document.querySelector('.sheet[data-open]');
    document.querySelectorAll('.sheet[data-open]').forEach((s) => s.removeAttribute('data-open'));
    setInert(false);
    document.body.style.overflow = '';
    if (wasOpen) lastFocus?.focus?.({ preventScroll: true });
    lastFocus = null;
  }
  ```
  С `inert` Tab не выходит за пределы окна: после последнего элемента фокус уходит в интерфейс браузера и возвращается в диалог.
- **Как проверить:** открыть меню клавишей Enter. Фокус должен стоять на «Закрыть». 70 нажатий Tab не должны выводить фокус за `#drawer`. Escape должен вернуть фокус на кнопку «Меню».

### 3. На главной не видно фокус в верхней панели (тёмная шапка)

- **Страница:** `/` (первый экран, пока шапка тёмная, класс `html.starts-dark`).
- **WCAG:** 2.4.7 Focus Visible (AA). Для сведения: не выполнен и 2.4.13 Focus Appearance (AAA).
- **Доказательство:** рамка `outline: 2px solid var(--brand-ink)` (`#0b4a43`) на фоне `rgb(10 46 42 / .55)` поверх `--night`. По пикселям контраст рамки к фону 1,22–1,46:1:
  - `a.brand` — 1,46;
  - `.tb-nav a` «Темы», «Локальным», «Экспатам», «Частые вопросы» — 1,44–1,45;
  - `button.tb-icon[data-sheet=search]` — 1,25;
  - `button.tb-menu` — 1,22–1,25.

  На скриншоте рамки у фокуса на «Меню» не видно.
- **Исправление** (`src/styles/global.css`, рядом с `.on-dark :focus-visible`):
  ```css
  html.starts-dark .topbar:not(.is-scrolled) :focus-visible { outline-color: var(--on-night); }
  ```
  `#f2f5f3` на `#0a2e2a` даёт 13,3:1.

### 4. На телефоне фокус уезжает под нижнюю панель (dock)

- **Страницы:** все на ширине меньше 960 px.
- **WCAG:** 2.4.11 Focus Not Obscured (Minimum) (AA).
- **Доказательство:** обход Tab по 7 страницам на 390×844, 385 остановок фокуса. **20 раз фокус полностью скрыт** под `.dock`, 111 раз — частично (42–84%). Примеры:
  - `/expat/`: «Отдых и поездки», «Первые дни в банке» — 100%;
  - `/topic/work/`, `/guide/car-import/`, `/guide/emergency/`, `/404.html`: ссылки подвала «Экстренные номера», «Контакты» — 100%;
  - `/faq/`: `summary` вопросов — 56–84%.

  Причина: у `html` задан `scroll-padding-top: 96px`, а снизу отступа нет. Браузер докручивает фокус до самого нижнего края экрана, то есть под док.
- **Исправление (проверено: 0 полностью и 0 частично скрытых):**
  ```css
  @media (max-width: 959.98px) {
    html { scroll-padding-bottom: calc(var(--dock-h) + 24px + env(safe-area-inset-bottom)); }
  }
  ```

### 5. Главная кнопка «Я локальный кандидат»: контраст 3,14:1

- **Страница:** `/`, `.hero-actions a.pill.pill-mint`.
- **WCAG:** 1.4.3 Contrast (Minimum) (AA). Текст 16 px / 650 — это обычный текст, нужно 4,5:1.
- **Доказательство:** `#ffffff` на `#1aa752` (`--brand`) = 3,14:1. Замер по пикселям на обеих ширинах дал тот же результат.
- **Исправление** (`.pill-mint` в `global.css`), любой из вариантов:
  - тёмный текст на фирменном зелёном: `color: var(--night)` — 4,66:1, фирменный цвет кнопки сохраняется;
  - или затемнить фон: `background: #13843f` — 4,77:1 с белым.

  Цвет `--brand` (`#1aa752`) **нельзя использовать для текста** на светлом фоне (2,85:1 на `--paper`) и под белым текстом. Оставить его только для заливок и иконок.

### 6. Увеличенный шрифт (200%): шапка и док ломаются, «Перейти к содержанию» видна постоянно, горизонтальная прокрутка

- **Страницы:** все. Измерено при `html { font-size: 200% }`: так ведёт себя Chrome на Android при крупном системном шрифте, а также Firefox в режиме «только текст».
- **WCAG:** 1.4.4 Resize Text (AA), 1.4.10 Reflow (AA).
- **Доказательство:**
  - **`.skip`** спрятана через `top: -60px`. При двойном шрифте ссылка выше 60 px и **постоянно торчит поверх шапки**: на скриншоте читается «…содержанию» и перекрыт логотип.
  - **`.topbar-in`** имеет фиксированную `height: var(--bar-h)` (56 px), а содержимое занимает 82–86 px. Надпись «Hamkor Bank» переносится и вылезает за пределы шапки (`.brand` 108 px). На 1440 пункт «Частые вопросы» в две строки наезжает на контент.
  - **`.dock`**: `height: 64px`, содержимое 67 px. Подписи слипаются: «ВопросыГлавная».
  - **Горизонтальная прокрутка** при ширине окна 390:

    | Страница | Ширина документа | Что вылезает |
    |---|---|---|
    | `/` | 437 px | `.topic-grid` (две колонки `1fr 1fr` не сжимаются) |
    | `/expat/` | 497 px | `.chapter-head h2`, `.steps strong`/`.step-lead`, `.round-arrow` |
    | `/local/` | 407 px | |
    | `/topic/work/` | 416 px | `.pager .next` |
    | `/guide/bank-card/` | 448 px | `.pager .next` |
    | `/guide/car-import/` | 458 px | `.pager .next` |
    | `/guide/arrival-72h/` | 452 px | `.faq-item .plus` |

  - Без увеличения шрифта ширина 320 px и интервалы по 1.4.12 проходят чисто (см. «Что работает»).
- **Исправление** (`global.css`):
  ```css
  .skip { top: 12px; transform: translateY(calc(-100% - 24px)); }
  .skip:focus { transform: none; }

  :root { --bar-h: 3.5rem; --dock-h: 4rem; }          /* растут вместе со шрифтом */
  .topbar-in { height: auto; min-height: var(--bar-h); }
  .dock { height: auto; min-height: var(--dock-h); }
  .dock a, .dock button { min-width: 0; text-align: center; line-height: 1.1; overflow-wrap: anywhere; }

  .topic-grid { grid-template-columns: repeat(auto-fill, minmax(min(100%, 10rem), 1fr)); }
  .topic-card, .steps a > *, .chapter-head h2, .pager a { min-width: 0; overflow-wrap: anywhere; hyphens: auto; }
  .pager { grid-template-columns: repeat(auto-fit, minmax(min(100%, 11rem), 1fr)); }
  .pager .next { grid-column: auto; }
  ```
  Подумать о том, чтобы при `.tb-back` прятать текст `.brand-name` (знак плюс `aria-label` уже дают имя) — так шапка не будет переноситься.

## Умеренные

### 7. Невидимая кнопка «Подсказка гида» получает фокус

- **Страницы:** `/guide/*`.
- **WCAG:** 2.4.7 Focus Visible (AA), 2.4.3 Focus Order (A). Axe: `region` (moderate) — содержимое вне ориентиров (`small[data-k="label"]`, `span[data-k="text"]`).
- **Доказательство:**
  - `.guide-fab` вставляется в конец `<body>`, после подвала. Пока он скрыт (нет `.is-visible`), у него `opacity: 0`, но `button.guide-fab-btn` остаётся в порядке Tab (`tabIndex 0`).
  - В обходе Tab на `/guide/arrival-72h/`, `/guide/bank-card/`, `/guide/car-import/` фокус попадает на кнопку с `opacity 0`, то есть исчезает с экрана.
  - Из поиска первый Tab тоже уводит сюда.
  - Ссылка «Следующий шаг» в пузыре стоит в DOM **до** кнопки (визуально порядок меняет `order: 1`). После Enter на кнопке Tab уходит не в пузырь, а в начало страницы.
- **Исправление:**
  ```css
  .guide-fab { visibility: hidden; transition: opacity 300ms var(--ease), transform 400ms var(--ease), visibility 0s 400ms; }
  .guide-fab.is-visible { visibility: visible; transition-delay: 0s; }
  ```
  В `followingGuide()` поставить кнопку в DOM перед `.guide-fab-bubble` (визуальный порядок задать через `order` у пузыря). Вставлять `fab` внутрь `<main>`: `article.after(fab)` вместо `document.body.append(fab)`. Тогда исчезнет и ошибка `region`.

### 8. Автоматическое движение без паузы: демо телефона и бесконечные анимации

- **Страницы:**
  - демо телефона: `/guide/arrival-72h/` (`.phone-demo`);
  - зацикленные иллюстрации: `/`, хабы, темы, статьи (`.illus.is-on` — `pl-bob`, `car-idle`, `cd-tap`, `hs-sway` и т.д. с `infinite`);
  - моргание глаз гида: `.guide-face .eyes`, `blink 5.2s infinite`.
- **WCAG:** 2.2.2 Pause, Stop, Hide (A). Движение начинается само, длится больше 5 с, идёт параллельно с текстом и не имеет кнопки «Пауза».
- **Доказательство:**
  - Демо меняет экраны каждые 2,4–2,6 с по кругу, пока оно на экране (`play()` → `setTimeout(... i++; play())`).
  - В режиме `prefers-reduced-motion` всё корректно останавливается (проверено). Но WCAG требует механизм паузы для всех, а не только для тех, кто включил системную настройку.
- **Исправление:**
  - В `phoneDemos()` добавить в `figcaption` кнопку `<button type="button" class="pd-toggle" aria-pressed="false">Пауза</button>`, которая останавливает и возобновляет `play()`. Либо проигрывать один круг и останавливаться.
  - Для иллюстраций и глаз ограничить повторы, чтобы движение укладывалось в 5 с: `animation-iteration-count: 2`, или снимать `.is-on` через 5 с.
  - Кнопки шагов демо управляют картинкой с `aria-hidden`, и диктор не получает никакой обратной связи. Достаточно `aria-pressed` на активном шаге.

### 9. Статусы поиска и фильтра FAQ: не объявляются или объявляются потоком

- **Страницы:** все (поиск), `/faq/` (фильтр).
- **WCAG:** 4.1.3 Status Messages (AA).
- **Доказательство:**
  - `ul#search-results` имеет `aria-live="polite"`. На каждый ввод (с задержкой 90 мс) список перерисовывается целиком, и диктор начинает зачитывать до 12 результатов со сниппетами.
  - «Ничего не нашлось…» пишется в `#search-hint`, у которого нет live-атрибута, поэтому это не объявляется.

  - в `Base.astro` после поля добавить `<p id="search-status" class="visually-hidden" role="status"></p>`;

  - `#faq-empty` оставить видимой подсказкой.

### 10. Горячая клавиша «/» без возможности отключить

### 11. Нетекстовый контраст: границы полей поиска и текущий пункт верхнего меню

### 12. Таблицы в статьях: `display:block` и прокрутка без клавиатуры

### 21. Шторка замедляет каждый переход

Это не нарушение, а заметка о качестве.

- Без «уменьшения движения» каждый клик по ссылке задерживается на 480 мс, а экран закрыт примерно 1,25 с.
- Замер при переходе с клавиатуры: `is-covering` 0–520 мс, `is-lifting` до ~1 250 мс.
- Фокус шторка **не крадёт**: после перехода он стоит на `body`, как при обычной загрузке. У самой шторки `aria-hidden` и `pointer-events: none`.
- С `prefers-reduced-motion` шторки нет совсем (проверено). Можно сократить время до ~250 мс.

### 22. Страница 404 на тестовом сервере

- Сервер на `:4600` (`python -m http.server`) на несуществующий адрес отдаёт стандартную страницу «Error response» (`lang` нет, `main` нет; axe: `landmark-one-main`, `region`). Фирменная `dist/404.html` проверялась напрямую по `/404.html`, с ней всё в порядке.
- **Что сделать:** на боевом хостинге убедиться, что для 404 отдаётся `404.html` со статусом 404. Netlify, Vercel и Cloudflare Pages делают это сами; для nginx нужно `error_page 404 /404.html;`.

## Что работает хорошо (сохранить)

- **Axe:** на всех 10 страницах и на `/404.html`, на обеих ширинах, нет ни одного нарушения уровня A/AA. Единственное нарушение — `region` от плавающего гида (п. 7).   - чипы (`--ink-2` на `--paper-2`): 6,74:1;
  - `.chip.ok`;
  - подписи дока (`--on-night-2` на доке): около 7,7:1;
  - подвал и подписи на тёмном первом экране.

  Делать `--ink-3` светлее нельзя.
- **Цели касания** не меньше 24 px везде. Иконки шапки 44×44, сегменты 44 px, пункты меню 44 px, вопросы FAQ 64 px.

## Как перепроверить

Скрипты аудита лежат во временной папке и в репозиторий не входят: `axe.cjs`, `contrast.cjs`, `keys.cjs`, `dialogs.cjs`, `motion.cjs`, `verifyfix.cjs`. Их стоит перенести в `guidebook/scripts/` и прогонять на каждой сборке. Обязательные проверки:

- axe без нарушений;
- в обходе Tab нет фокуса с `opacity 0` и нет фокуса, на 100% скрытого доком;
- 70 нажатий Tab в открытом меню не выводят фокус наружу;
- при заблокированном `/_astro/*.js` шторка исчезает за 2 с;
- при `font-size: 200%` у страниц `scrollWidth == clientWidth`.
